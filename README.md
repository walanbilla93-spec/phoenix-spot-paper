# Unified two-confirmation paper research 0.9

The detector, zone source, baseline entry model, structural stops and price-path exit functions remain frozen. No exchange orders, trading keys or settings changes.

Only evaluation controls and parallel variants change:

* The first accepted signal receipt starts the 28-day clock. Holdout begins exactly 70% of 28 days later (19 days, 14 hours, 24 minutes). It uses UTC time, never a changing signal percentile. The persistent clock file is created exclusively, read-only, hash-checked against an immutable SQLite meta row, and verified on restart, reporting and export. A mismatch fails closed.
* Target: 150 distinct fixed UTC five-minute time clusters across all coins, after at least 28 days. Reports show both deduplicated coin/direction signals and time clusters. Nearby clusters may still be correlated; these are not proof of statistical independence.
* Holdout terminal outcomes are suppressed before event-chain and public logging. All capture archive scopes also redact old terminal records one gzip member at a time, using a disk spool, 2 MiB line cap and 64 KiB transfer buffers. The private trial database and result CSV remain unexported until the final kill check completes. Every research download includes a privacy audit. Underlying public market prices remain replayable; do not manually reconstruct reserved outcomes.
* Delayed REST context is merged into bounded time-sorted caches instead of discarded behind live candles. First-seen availability is preserved. Completed exchange five-minute candles fill the startup partial-window gap. No past signal context is rewritten. Incomplete context is flagged; missing five-minute ATR or volume ratio excludes only wider-stop.
* Five parallel plans on new signals: unchanged confirmation-close `baseline`; unchanged maker-touch `limit`; unchanged ATR `wide_stop`; `limit_through` requiring one tick beyond the zone limit; and `arrival` using the fresh observed ask/bid at signal receipt plus the original adverse-fill allowance. Arrival keeps the original absolute stop and the same 1.5R/3R exit multiples. Price and basis-point gaps from confirmation close are recorded in per-signal context. Partial entry minutes use only post-entry public trade ticks, then the frozen full-minute exit paths. Missing partial-minute observation censors arrival. Maker variants remain hypothetical fills without queue verification.
* R1-to-R2 amendment is allowed only before holdout. A private SQLite backup is created. Existing signals, three original plans, labels and outcomes are retained; the new variants are not fabricated retrospectively. The first new-variant signal ID is recorded. Nothing is reset or deleted.

Public performance reports remain locked during collection. Final release requires matured positions, the frozen filter hash and the kill check: stop a variant when lower-bound holdout net R <= 0 or gross R < 0; censored final trades stop it as inconclusive. The 24h development purge remains. The chosen holdout date never moves if reaching 150 clusters takes longer than 28 days.

Run `python -m unittest -v`. Repair-specific coverage is in `test_trial_repairs.py`; saved-reference parity checks all 92 resolved original outcomes when the external reference is available. The three PostgreSQL integration tests require disposable PostgreSQL and are unrelated to this recorder. Memory/caps remain 512 active plans, 10,000 signals, bounded caches, 64 MiB trial SQLite and the existing 2 GB volume limit.
